## 为什么做这个聚合

本地跑大模型,**硬件路线决定一切**——AMD 核显走 Vulkan、NVIDIA 走 CUDA/vLLM、Apple 走 Metal,引擎、量化格式、调参、踩的坑全不一样。网上零散的教程往往不说清"这是哪个硬件、哪个后端",照着抄经常翻车。

这里每一篇都**锁定具体硬件 + 具体后端**,并且是**作者实机跑通、记录了真实速度和所有踩过的坑**的。目标是:拿到一台什么机器,能直接翻到对应那篇,照着走一遍就能搭起来。

## 通用经验(跨硬件都适用)

- **先验证驱动认对了 GPU**,再谈速度——掉软渲染是最常见的"慢到不能用"根因;
- **量化档位 = 质量 vs 速度 vs 显存的三角**,没有免费午餐;MoE 架构能"大而不慢"是特例;
- **投机解码(MTP / draft)在对的硬件+模型上是真收益**,但参数要按实测调,盲目照抄别的平台的值经常负优化;
- **上下文长度有物理天花板**,KV cache 吃显存,超了会 OOM 甚至把驱动搞崩——每篇都标了实测边界;
- **生产化 = systemd/容器自启 + 看门狗 + 鉴权 + 防火墙**,不是把命令跑起来就完。

# Qwen3.8-27B @ RTX PRO 6000(实测评测)

> 一句话结论:27B 稠密模型在这张 Blackwell 专业卡上**快得不像话**——Q8 全精度下文本
> ~95 t/s,是**同款 27B Q8** 在 AMD AI Max+ 395 上(~16-20 t/s)的**约 5 倍**;256K 上下文单卡直接开,
> 显存只吃一半。作为"日常主力 + 长文档"用非常舒服。
>
> ⚠️ **别把这里的"395 ~16-20 t/s"当成 395 的全部水平**:这是**稠密 27B 的 Q8** 数字。同一台 395 上
> 换 **Q4** 量化约 ~28 t/s;而跑 **Flash-Next(125B MoE,激活仅 6B)** 能到 **29-40 t/s**——MoE 稀疏
> 架构在核显上"大而不慢",和稠密模型是两回事,数字不可混为一谈。

---

## 一、测试环境

| 项 | 值 |
|---|---|
| GPU | NVIDIA RTX PRO 6000 Blackwell,96GB,compute cap 12.0 |
| 引擎 | llama.cpp CUDA 预编译版(build-cuda13),router 模式 |
| 模型 | Qwen3.8-27B(稠密,非 MoE),**Q8_0** 量化(近无损),含 MTP 草稿头 + mmproj 视觉头 |
| 上下文配置 | `--ctx-size 262144`(256K)单槽 |
| 对照组 | 同款 27B Q8 在 AMD Ryzen AI Max+ 395(Vulkan)上 |

**说明:27B 是稠密模型**(每 token 激活全部 27B 参数),和同系列的 Flash-Next(125B MoE 激活 6B)、35B-A3B(MoE)是完全不同的路子——稠密模型速度受显存带宽和算力直接约束,这正是专业卡能拉开差距的地方。

## 二、实测数据

| 指标 | 实测 | 备注 |
|---|---|---|
| 文本生成(Q8_0) | **~95 t/s** | 短问答单次测 |
| 文本生成(后换 abliterated 改版 Q8) | **~86 t/s** | 去审查改版,速度略降属正常 |
| 视觉(看图/OCR 类) | **~20 t/s** | 发票图,识别准确;多模态吞吐天然低于纯文本 |
| MTP 草稿接受率 | ~0.64 | 规整任务更高,发散创作更低 |
| 显存占用 | **~53GB / 96GB** | 27B 单模型 + 256K KV + MTP 草稿头,只用一半多 |
| 单请求上下文 | **256K** 直接开 | 稠密 27B KV cache 不大,不像 Flash-Next 那样紧张 |

### 与 AMD AI Max+ 395 对照(同款 27B Q8)

| 平台 | 文本速度 | 架构差异 |
|---|---|---|
| **RTX PRO 6000(本文)** | **~95 t/s**(Q8) | 独显 GDDR7,显存带宽 + FP 算力碾压 |
| AMD AI Max+ 395(Strix Halo) | **~16-20 t/s(Q8)** / ~28 t/s(Q4) | 核显 + 统一内存,带宽是瓶颈 |

> **量化口径对齐**:上表是**同款 27B 同为 Q8** 的苹果对苹果比较(395 实测 Qwen3.6-27B Q8 ~17.5、
> Qwen3.8-27B Q8 ~15.9 t/s,取整 ~16-20)。395 换 **Q4** 能到 ~28 t/s,但那是降精度换速度,和本文 Q8 不同档,
> 不要直接拿 395 的 Q4 数去比本文的 Q8 数。

约 **5 倍差距**(Q8 对 Q8)。27B 这种稠密模型对带宽极敏感,是最能体现专业独显价值的负载类型。

> **再强调一次,避免看串**:395 上的 **Flash-Next(125B MoE)能跑 29-40 t/s**,**比** 395 上的稠密 27B Q8
> (16-20)**还快**——这不矛盾,因为 MoE 每 token 只激活 ~6B,核显带宽压力小得多。所以"395 慢"只对**稠密模型**
> 成立;稀疏 MoE 在 395 上反而很能打(详见仓库里 395 篇的 Flash-Next)。

## 三、体验评价(主观,基于实际使用)

**优点**
- **快到"无感等待"**:95 t/s 下,几百字回答基本是"话音刚落就写完",交互体验和云端商用 API 接近。
- **Q8 近无损**:不是为了塞进显存牺牲精度的 Q4,是接近原版权重的 Q8,质量该有的都有。
- **256K 上下文白送**:稠密 27B 的 KV cache 占用远小于超大 MoE,这张卡开 256K 毫无压力,显存还剩一半——长文档/长对话很从容。
- **显存余量大**:只吃 ~53GB,意味着还能在同卡并存别的小模型(如 OCR、embedding),或开更高并发。

**代价 / 注意**
- **27B 稠密的"天花板"就在 27B**:它不是 Flash-Next 那种 125B 级的知识量和能力,定位是"又快又稳的日常主力",不是"最强脑力"。要顶级能力得上 Flash-Next(但那个上下文和部署复杂度是另一回事)。
- **视觉吞吐一般**(~20 t/s):看图能力在,但速度明显低于纯文本,批量 OCR 场景不如专用 OCR 模型(同卡上 PaddleOCR-VL 实测 ~1000 t/s 级)。
- abliterated 改版有轻微速度损失,且指令遵循可能受影响——追求稳定的正经用途优先用官方原版。

## 四、选型建议:27B 还是 Flash-Next?(同卡上)

这张卡两个都能跑,但抢显存,通常不同时常驻。怎么选:

| 需求 | 选 |
|---|---|
| 日常对话、写作、代码、快速响应、要 Q8 高质量 + 长上下文 | **Qwen3.8-27B**(本文) |
| 最强模型能力、复杂推理、能接受 24K-100K 上下文和 25 分钟冷启动 | Flash-Next 125B(见 rtx-pro-6000 runbook) |
| 高频批量 OCR / 票据识别 | 专用 OCR 模型(PaddleOCR-VL) |

个人体感:**27B 是这张卡上"性价比最高的日用档"**——部署简单(标准 llama.cpp,不用折腾专用镜像和 PLE 表)、快、上下文大、质量够。Flash-Next 是"要顶配再上"的选择。

## 附:一句话记住

- 27B Q8 @ RTX PRO 6000:**~95 t/s 文本**,256K 上下文,显存 ~53GB,是 AMD 395 同款 Q8(~16-20 t/s)的 ~5 倍
